Call it sandbox pilot testing. Mid-November matches the Phase 1 sandbox gate in the agreed architecture (synthetic data, zero touch on Chayne systems), not the later pilot on a live shadow feed. Say “pilot testing in the sandbox” to Travis so nobody expects production data by then.

What Travis asked for

  • Phase one is the base layer: the Movement Record ID (MRID) and the evidence it carries. One movement's complete evidence chain as one exportable artifact, in minutes, with no manual stitching (his Q10.2).
  • Add-ons later: zero-knowledge selective disclosure and the agent layer, once the base layer works.
  • Architecture that travels: built with Salt and Parsera in mind, so the same design rolls into Salt's and Parsera's portfolios.
  • Timing: flexible launch, but first testing by about mid-November, with a few small subscriptions he can activate.

Scope

Everything below runs in the Q² sandbox on synthetic data, with the Salt adapter tested against a Salt test tenant. The first corridor is LP subscriptions, built negative path first.

Out of scope for this price

  • Selective disclosure (ZK proofs). Phase 2 or later, priced separately.
  • Agent layer and smart-account (ERC-4337) build.
  • Live Chayne, Salt mainnet or Parsera production data.
  • LP and NAV reporting, KYB and accreditation files.
  • Any key material, origination or bypass path. Never.

Reusable for the next fund

  • Movement Record service, export and seal: generic core.
  • Eligibility engine: rules are configuration, not code.
  • Salt adapter: works for any Salt customer with a wrapper.
  • Negative-path library: Chayne's scenarios become templates.
  • Chayne-specific: limit values, corridor definitions, report shapes.

Acceptance criteria for the 13 November test

  • All eight negative-path scenarios refuse, visibly, with the right reason code, and none can be overridden.
  • One approved subscription movement produces a complete Movement Evidence Chain export in minutes, with no manual step.
  • Tampering with any recorded fact is detected by chain verification.
  • The Salt transaction id is bound to the MRID at submission, and every Salt state change is recorded.
  • No key material, credentials or investor PII ever reach Q².
